## Decisions

- **D-01** The habit guard gains a sixth shape, `gitDashC`'s sibling for the capital form: `git -C <path> <anything>` and `git -C<path> ...` are denied for EVERY verb, on both tools, with the hint "run git bare from the repository root; read a foreign tree with the file tools (Read / Grep / Glob), never with `git -C`". The three `git -C <projectRoot> push|merge|rebase` ask rules stay in the ruleset and in `ownedAskRules` - no `reconcile-ask-ruleset` op - because the ask rules are the harness-native backstop for a project whose hooks are off (`ORCHESTRATOR.md` § Commit & Push Authority: accident-grade, Gate 4 behind them). The selfcheck and spike rows that pin `git -C <path> status` as silent (RESEARCH facts 3-4, consumers) flip to the habit deny; the rows pinning `-C push` as ASK flip to the habit deny too, since the habit check runs first (fact 6). plan: GATES
- **D-02** The nested forms: `Push-Location`, `Pop-Location`, `popd` join `HABIT_DIRECTORY_CHANGERS`; `habitWordsOf` skips a leading call operator or block opener - `&`, `{`, `(`, `$(`, `.` (dot-sourcing) - before taking the segment's first word, so `& { Push-Location x }`, `$(cd x)`, `( cd x )`, `{ cd x; }` are judged by the word that follows. Quotes stay opaque (the documented limit, `docs/LOOP.md:131-132`, stands and is restated with the new forms). The PS `&` stays a non-separator: the call operator is now read through, which is the cheaper fix. plan: GATES
- **D-03** Gate 1's non-writer branch gains the main-session branch's outside-root passthrough (fact 8's `path.resolve` + `path.relative`, reused as one helper): a non-writer subagent's Edit / Write / MultiEdit / NotebookEdit passes through only when EVERY path field present in its `tool_input` (`file_path`, `notebook_path`) resolves OUTSIDE the project directory; one of them inside, a missing or unparseable field, or no path field at all -> the deny, byte-identical to today (round-1 B5: `targetPathOf` prefers `file_path` whatever the tool, so a mixed payload must not pass). `targetPathOf` itself and the main-session branch are unchanged. This is the code side of the roadmap's "one of the two", because the doctrine already sends procedure agents to write under the scratch directory and to fail a gate on a scratch copy (`ORCHESTRATOR.md.tmpl:224-244`, `:262-263`) and the main branch already holds the same boundary. Not a fail-direction change: an unreadable or unresolvable target still denies. `docs/LOOP.md:25-27` and the hook header gain the words "inside the project root". plan: GATES
- **D-04** The plan index may carry declared lines `Side by side: <REF>, <REF>[, <REF> ...]` at column 0 (zero or more lines; each names TWO OR MORE tickets that run beside each other; no upper bound). `plan-gate.js` parses them with the `Tickets:` line's discipline (`declaredTicketCap`, fact 10): an unknown or duplicate ref refuses with `sidebyside-unknown-ref:<line>`; a malformed line (fewer than two refs, a token that is not a ref) refuses with `sidebyside-malformed:<line>`; two refs of one line whose Code Map paths (fact 9's `codeMapPaths`) share a path refuse with `sidebyside-shared-path:<REF-a>,<REF-b>,<path>`, one problem per shared path - and "share" means equality OR containment: a directory row of one ticket contains every path under it in the other (`scripts/engine` and `scripts/engine/plan-gate.js` share), because a commit by path staging cannot separate them either; the problem names the longer path. No line = nothing checked. The tokens enter the doc header and `PG_CONTRACT_TOKENS`, each produced by one M-case on a two-ticket fixture. The planner brief and `plan.md § Plan readiness review` name the line; the Stratex sentence retires through the 0.3.12 `Retires local rules:` line. This plan declares no side-by-side pair: its tickets share the selfcheck and the spikes (D-10). plan: GATES
- **D-05** The review wrapper stops passing the engine's stream through. It sends codex's stdout and stderr to ONE log file outside the repository - `<temp>/pnp-codex/<key>-<class-or-role>-<timestamp>-<pid>.log` with `<temp>` = `$env:TEMP` (PS) / `${TMPDIR:-/tmp}` (bash), the QAL precedent (fact 20; its `<ts>-<guid>` form) - and takes the verdict from codex's own `-o <last-message file>` beside the log with the same stem. Concurrency (round-1 B3): the log and the `-o` file belong to the run that created them - timestamp plus PID make the name unique, no lock; the session-state file gains no new write path (the save / clear path stays as today, RESEARCH facts 16-18 and 21a-21b), and two runs with one key at once remain what they are today, the operator-held invariant of `ORCHESTRATOR.md` § Branch policy (one executing session per tree; a plan pass has its own key) - named, not changed. The wrapper takes the verdict (fact 24; `exec resume` carries the same flag, verified `codex exec resume --help`, codex-cli 0.156.1). The wrapper's stdout becomes the last message, byte for byte, so `skills/plan` Step 6's `> readiness-round.txt` and the `^BLOCKERS:` grep stand unchanged; its stderr carries the header line, then after the run: the tokens line (D-07), the capacity line when it applies (D-06), the log path as `codex-review: log <path>`, and the footer line (fact 15), in that order. The exit code stays codex's. The wrapper's stdout carries NOTHING but the last message: the PS `Write-Warning` of the unidentified-session path (`ps1:372`, selfcheck `psWarnsOnStdout` `:5518,5533`) moves to stderr, and when the engine leaves no `-o` file (died before its final message) the wrapper prints nothing on stdout and one stderr line `codex-review: no verdict - the engine wrote no final message; log <path>` before the footer, so a `^BLOCKERS:` grep that finds nothing is explained on stderr. ## Deferred

Back the moment GATES-004's emitter test fails: the ticket stops, and the fallback is chosen with the hex diff in hand - the candidates then are a node child process writing the bytes itself (no shell parsing, argv as an array) or a .NET process with redirected streams; never a shell string.
- The Gate 1 spike parity against a reference hook copy (`run-spikes.mjs:13`, `:47-52`): skipped when no reference is given; a reference run after D-03 would report a reason-text diff on the new passthrough case only. Back when a consumer runs the spikes with `--reference`.
- `& { ... }` and `$( ... )` holding a `git -C` or a pipe habit deeper than the first word (D-02 reads one leading operator, not an arbitrary nesting). Back when a harvest row shows such a form.
- The ask rules for `git -C <projectRoot> push|merge|rebase` left in the ruleset (D-01). Back if a consumer's selfcheck reports them unreachable as a defect.
- A per-pass token INCREMENT (D-07 prints the cumulative figure). Back when the wrapper stores the previous figure per session - a state-file change with its own migration.
- The QAL wrapper's output (D-08). Back when QAL is enabled anywhere.
- The remaining § CODEX items (PS-EOL drift, `multi_agent`, the round-file skeleton written by the wrapper, `readiness/<ABBR>/brief-pass<N>.txt`, an effort flag). They stay on the roadmap.
