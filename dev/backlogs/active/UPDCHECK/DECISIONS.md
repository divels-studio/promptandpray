# DECISIONS - UPDCHECK

## Decisions

- **D-01** The self-check that runs by itself after a writing apply proves ONLY the project it just wrote: its rendered artifacts, config, version stamps and ownership bookkeeping - no wrapper, hook or host execution and no negative control of the payload. Operator, dialog 2026-11-06, the question "what should the self-check that runs by itself after a project update prove?", answer verbatim „Само проектът" (the option: "checks only the written files, settings and versions of the project, without running wrappers; fastest and almost does not grow; a missing bash or PowerShell is then found only at the first audit"). plan: UPDCHECK
- **D-02** The full run stays the default and stays everywhere it runs today: CI (`.github/workflows/ci.yml`, no-fixture form), this repository's `verify.commands` row `selfcheck`, and a manual `/pnp:selfcheck` in any project. Every negative control keeps running there, so overrides § Architecture direction ("every assertion has a negative control or is printed as `[NOTE]`") holds unchanged: the project scope is a subset of the full run, never a replacement for it. Source: the premise of the D-01 dialog, verbatim „Пълната проверка във всички случаи остава в CI, тук при разработката и при ръчно пускане на /pnp:selfcheck". plan: UPDCHECK
- **D-03** The scope is selected by one engine flag, `--scope project|full` (absent = `full`); any other value exits 2 through the existing `bail` path, because a misspelled scope that silently ran something else is the false-green class the engine already refuses for a missing payload. Why a value flag and not a boolean: the CI and manual forms keep their argv byte for byte. plan: UPDCHECK
- **D-04** The project scope runs exactly the checks that read the real project passed as `--project-fixture` (today `sectionProjectLayer` and `sectionCommitAutomation`, plus any check in another section that reads `PROJECT`, e.g. `sectionPlanRefNaming(tmpRoot, PROJECT)`); the set is enumerated by a closing grep of `PROJECT` in `scripts/selfcheck/aiwf-selfcheck.js` and copied into the plan index. It spawns no PowerShell and no bash host: the host discovery at module load (`findPwsh`, `findBash`) runs only when the full scope needs it. Why: D-01 excludes host execution, and a host probe at load would keep its cost and its failure mode on the apply path. plan: UPDCHECK
- **D-05** All four callers of `finishWithSelfCheck` - `/pnp:update` (`scripts/update/aiwf-update.mjs`), setup (`scripts/setup/generate.mjs`, `scripts/setup/interview.mjs`) and `/pnp:roles` (`scripts/setup/aiwf-roles.mjs`) - take the project scope: the one spawn in `scripts/selfcheck/run-selfcheck.mjs` passes `--scope project`. Why: its contract is that the callers "reach the SAME verdict from the same child process", and each of them reports on the project it just wrote - the subject D-01 names. The child and the caller ship in the same plugin root, so the flag can never meet an engine that lacks it. plan: UPDCHECK
- **D-06** The output contract stays: the tally line `==== P/T assertions passed ====` is unchanged (parsed by `scripts/update/test-update.mjs` and matched by `scripts/setup/test-setup.mjs`), and the scope is printed as one header line beside `plugin root` / `project layer`. The operator sees the narrower claim in words: the PASS line the caller prints names the scope (e.g. "project layer only - run `/pnp:selfcheck` for the full check"), and `skills/update/SKILL.md`, `skills/setup/SKILL.md`, `skills/selfcheck/SKILL.md` say what the embedded run proves and what it no longer proves. plan: UPDCHECK
- **D-07** The project scope gets its own negative control: on a deliberately broken copy of a project layer it exits 1 and names the broken check, and on the same copy the full scope's own reading of it - `projectLayerFindings`, the function `sectionProjectLayer` reports - finds the same check not ok, in-process (clarified after round 1, B2: a second full child per run would add the whole full run to every full run, and NEGATIVE CONTROLS already prove the full scope fails on a broken project layer) - so the narrowed run is proven able to fail, not only to pass. A second control pins the scope boundary: the project-scope run prints none of the payload section titles. plan: UPDCHECK
- **D-08** Nothing in the self-check is treated as about to retire. Operator, dialog 2026-11-06, the question "is anything in the self-check about to be dropped, so it is not worth speeding up?", answer verbatim „Не знам, реши ти"; the COO's call: no section is planned around a removal. plan: UPDCHECK
- **D-09** The time is measured, not promised: the plan records the embedded self-check's wall time on this repository's self-install apply before (the full run, 701 s standalone on 2026-11-06, ROADMAP § UPDCHECK) and after, with the command that produced each number. No time bound is written as an acceptance threshold: the bound is structural (D-04's fixed set of checks), because a number measured on one machine is not a contract. plan: UPDCHECK
- **D-10** The change ships as a release (overrides § Release discipline): the version bump in `.claude-plugin/plugin.json`, one `note` migration (the engine and skill changes are payload read from the plugin root, no managed artifact is re-rendered), and a `CHANGELOG.md` block ending `Retires local rules: none`. plan: UPDCHECK
- **D-11** This repository's prose-only release rule (overrides § Test policy: "`validate-payload` + the self-install `/pnp:update --apply` ... with its embedded self-check; NO suite locally - CI runs the full set after the push") keeps its text; after D-05 its embedded self-check proves the project layer only, and the payload's prose checks (PAYLOAD INTEGRITY, PROVENANCE) are proven by `validate-payload` and the provenance grep locally and by the full self-check in CI after the push - a red CI leg stays a defect ticket, not a release block (§ Release discipline). Why: the rule already names CI as the full set's home; no new local run is added. plan: UPDCHECK

## Deferred

- Speeding up the slow payload sections themselves (the repeated full passes in WRAPPERS PowerShell RESUME CONTROLS and the bash channel, the whole-payload copy per EXAMPLE FIXTURE control) - after D-01 they leave the apply path and cost only CI and this repository's VERIFY row; returns with ROADMAP § SUITES, or when a consumer runs `/pnp:selfcheck` often enough that its full time is reported as a problem.
- A per-section wall-time print in the self-check output - returns when a second measurement of the full run is needed (D-09 measures from outside the process).
- A `--scope` value for the payload's static checks only (PAYLOAD INTEGRITY, PROVENANCE, HOOK WIRING) on the apply path - returns if a consumer installation is found with a corrupted payload cache that the project scope did not catch.
