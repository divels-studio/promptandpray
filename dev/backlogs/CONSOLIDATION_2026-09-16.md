## A. Doctrine sync across consumers (the root problem; zero new gates)

- **D1.** One transfer surface per consumer — a CANDIDATES-class FILE. The consumer READS the
  surface; the operator points, never transcribes (the one measured sync garble lived in the
  human-typed fragment; all file-read transfers arrived intact).
- **D2.** Doctrine-class text born in any other home (plan process sections, memory,
  operator-zone CLAUDE.md) gets a same-moment one-line pointer row on the transfer surface —
  riding the EXISTING doctrine-write gate: text + pointer row are shown and approved together.
  When the multi-session window (D7) is closed: queued with the approved text frozen, landing
  immediately after the executing ticket's commit, never re-asked (mechanism field-proven).
- **D3.** Archive-time backstop: the plan-archive step greps process sections for rule-class
  points lacking pointer rows; fail-capable, positive control on a known-dirty plan.
- **D4.** Event-driven cleanup: a release's CHANGES report lists superseded consumer-local
  rules; acting on that list is part of the consumer's update ritual. Memory-driven cleanup is
  dead (measured: a drift note went stale 47 minutes after recording, carried into a brief a
  day later).
- **D5.** Live conflicts and rulings travel by direct cross-session escalation; the operator is
  never a courier. Doctrine only — the transport exists and is field-proven (this consolidation
  ran on it); no new machinery.
- **D6.** A migration introducing a word-gate warns in CHANGES: "check your local rules for
  self-initiated X".

## B. Payload doctrine adoptions (stack-neutral)

- **D7.** Multi-session invariants into WORKFLOW § Branch policy, adopted VERBATIM from the
  originating text (born Furnissimo PLAN_PROJ §Процес т.9, currently in two consumers and no
  authoritative home): on one working tree exactly ONE executing session; non-executing
  sessions may READ — zero repo writes, zero DB operations, zero paid auditor passes. The
  machine-wide "exactly one live auditor" clause is SCOPED TO MEASUREMENT (operator
  clarification 2026-09-16): it holds while a pass's counter start/stop pair is being recorded —
  otherwise the pair is not attributable — and is NOT a general work restriction. It is an
  OPERATOR-HELD invariant (no hook can see sibling sessions), written in the honest-limits
  register.
- **D8.** Guard (b) extension: a newborn ticket's announcement carries ONE question — does it
  get an audit pass; the answer lands in its PLAN entry. A question, never an automatic pass.
- **D9.** Host-directive precedence: project canon beats host ergonomic directives; host
  safety/permission rules are never overridden (three instances across two projects).
- **D10.** Doctrine-write gate: rule-bearing writes (memory or files) are shown and land on
  approval; purely factual statuses exempt.
- **D11.** Closing-grep law into the tripwires: enumeration ends when the grep for the symbol,
  the invalidated phrase/count, AND the bare pointer form returns zero outside the list —
  fail-capable with positive control. Every NEW OR CHANGED evidentiary instrument is made to
  fail on purpose before it is trusted; retroactive proofing of pre-existing instruments is a
  deliberate ticket, never an ambient duty.

## C. Orchestrator role (rendered like the writer; generic; references payload doctrine, never restates it)

- **D12.** Core rules: data discipline (source in every sentence with a number; operator-only
  data is ASKED for, never promised; arithmetic over two measurements is not a measurement);
  the literal coverage line before every paid dispatch, written INTO the brief text — for
  review briefs the fixed-path file header "COVERED BY: operator word <quote>, <date>" (makes
  compliance grep-able on a project artifact); verdict and next dispatch never in one message;
  canon conflict → stop (absorbs D9); doctrine-write participation (D2's show-both); direct
  escalation with the D18 trigger list; the four-classifier channel filter (decision? / his
  gate, carried as something visible? / real in this environment? / confession → ledger, not
  channel). Numeric targets stay OUT of rendered role text — diagnostic medians live in
  analysis docs (Goodhart).
- **D13.** Chain-trace duty: before the first paid readiness pass, for every Outcome sentence
  the COO dives and AUTHORS a chain table {behavior | ordered file:line links from the entry
  point | endpoint class}, and acts on findings before dispatch. Catch-share measured on a
  small self-classified sample (~15 blockers, 2 plans, classified by the producing COO):
  ~75-80% form-catchable missing-segment class, ~20% judgment-only; the form check verifies
  coverage and resolution, never attention — stated in the duty text.
- **D14.** The fact-check gate grows ONE clause (no new agent, no new pass), sibling of "every
  acceptance command exists and can fail": verify the chain table's FORM — every Outcome has a
  row, links resolve at their file:line, endpoints are source/render-or-DB-write, chains start
  at the entry point.
- **D15.** Duals law (spec-design rule): every obligation that COMMANDS an action ships with
  its suppression dual — the paired rule saying when NOT to do the obliged thing; a spec
  section with such an obligation and no dual is returned at review. Prohibitions and operator
  gates ("never X", "only on the operator's word") are not obligations in this sense and carry
  no dual. (Root: the generation-2 pendulum, measured independently in both projects. Honest
  limit: a dual with zero events is ambiguous — working silently vs dead letter; dual FAILURES
  still surface as operator corrections attributable to the dual, the only observable that
  matters.)
- **D16.** Rule-health signal via the EVENT ledger only: violations, catches, and operator
  corrections attributable to a rule (all rare, already narrated). A rule with zero catches and
  zero violations across N missions is the removal candidate; an obligation accumulating events
  while its dual accumulates none is the duals-law falsifier. The happy path is never
  instrumented.
- **D17.** References only, never restatements: stop semantics, subagent model policy,
  multi-session invariants (D7), VERIFY honesty — all payload.

## D. Arbiter

- **D18.** No standing paid role. An escalation-TARGET session with: four COUNTABLE yes/no
  triggers — (1) the decision reverses a plan-recorded decision; (2) it touches access policy /
  tenancy / security-definer surfaces; (3) its blast radius crosses the current ticket's
  boundary; (4) two sessions/roles disagree in writing; — the rule "no ruling without an opened
  file"; a durable ruling ledger (one line: question / ruling / evidence pointer) as a named
  section OF the transfer-surface file, making the role resumable (succession, not a second
  arbiter); metric = catches vs introduced defects (seed rows: the honest 3/2 tally).
  "No Fable above Fable" recorded as an operator structural decision, not evidence.

## E. Pass economics (doctrine)

- **D19.** Budget gates are planned and measured ONLY in operator-counter start/stop pairs;
  wall-clock duration recorded per pass; pairs comparable only in the same window state; tokens
  demoted to diagnostic. No doctrine sentence promises token costs as planning numbers.
  (Measured: пп-per-turn spread ±15% vs пп-per-token ±50% across the anomaly pair; gross
  request volume explains the bulk, mechanism unproven.)
- **D20.** Resume policy: correction-round verifications resume BY DEFAULT (anchoring: zero
  instances, two counter-instances); a correction round that RE-ARCHITECTED rather than closed
  blockers re-poses the whole-question — that verification reverts to cold or operator call;
  readiness pass 1 always cold; readiness N+1 may resume only with carried-list +
  re-read-from-disk + independent-consumer-search compensations, on the operator's word.
  Canonical text: resume answers "is the DELTA sound"; cold answers "is the WHOLE still sound".
- **D21.** Evidence pack as payload practice: pack on every first code-class pass + explicit
  spot-check right and duty; the claim is qualitative (moves the pass from rediscovery to
  judgment), never cost.
- **D22.** Stats methodology: normative text in ONE payload home (a short METRICS section);
  the TABLE lives on the project's never-archiving transfer-surface file (one per project —
  cross-plan comparability is what made the counter test possible); the active PLAN's process
  section carries only the D2 pointer row. No memory seeds, no rendered artifact.
- **D23.** The review skill's plan-readiness brief template gains the literal block
  "PREVIOUS PASS BLOCKERS (verbatim; absent or empty on pass ≥2 is a contract violation the
  Reviewer reports separately)" — omission becomes visible in the fixed-path brief artifact.
- **D24.** Disposition: HARD-013 gains the third instance and both exit-code faces (env-false
  red and legitimately red); the dropped HARD-014 topic is absorbed by D20; frozen HARD-010/011
  resume after the operator's decision; regulation v2 seeds the D12-D17 render and consumer
  local records gain D4 cleanup clauses.
